# 跑完测评后一键更新网站

首次准备：安装 Node.js 24 或更新版本、Git 和 GitHub CLI，运行 `gh auth login` 登录有本仓库写入与 Actions 权限的账号，并更新本地 wiki。请先提交或自行保存仓库中尚未提交的改动。

在强度测评中心完成标准档并启用基准后，回到 wiki 目录运行：

```powershell
.\Update-And-Publish.cmd
```

也可双击文件。默认使用已启用的个人标准基准，读取本机安装的游戏，自动选择下一个网站补丁版本。等待终端显示“发布成功”和网址；GitHub CI 与部署通常需要数分钟。

脚本依次同步天梯与百科、检查数据和构建、上传资源包、提交 PR 到 dev、等待 CI 并合并、启动数据发布、等待部署、核对线上站点版本和两档结果摘要。只发布生成数据，站点功能代码沿用 main，不会把 dev 中尚未发布的功能一起上线。仓库的审阅与分支保护要求仍然有效。

## 没有启用个人基准

直接指定完整后台批次目录，文件夹中需要保留汇总、CSV、天梯图片、raw 原始证据和测评说明：

```powershell
.\Update-And-Publish.cmd --run-directory "D:\测评结果\standard_20261022_090325_960"
```

## 常用选项

| 需要做什么 | 命令或附加参数 |
| --- | --- |
| 只查看来源与发布计划 | `--dry-run` |
| 仅本地同步和检查，不上传或发布 | `--prepare-only` |
| 使用不同游戏目录 | `--game-dir "D:\游戏\王国保卫战Dove版"` |
| 指定网站版本号 | `--version v1.8.0` |
| 更新快速档 | `--profile quick` |
| 使用指定测评说明 | `--methods "D:\测评标准与局限.md"` |
| 保留上次任务，改为发起新的同步 | `--new-run` |

标准和快速分别更新，另一档保留原批次。游戏目录同时支持安装文件夹和内层 KingdomRushDove 目录。测评说明默认优先使用已安装插件中的现行说明，找不到时使用批次附带说明。

使用 `--prepare-only` 检查完后，再执行同一命令并去掉这个选项，即可继续上传和发布。也可以使用 `npm run publish:update -- 参数`，该入口结束后不会等待按键。

## 中断与失败

关闭窗口、断网或执行失败后，先处理提示，再原样运行命令。脚本保存发布进度，会复用已有 PR 和发布任务，避免重复提交。CI 或部署失败时会给出 GitHub 链接；在 GitHub 修复并重新运行失败任务后，再执行原命令继续。

如果输入目录、批次内容或发布版本要改变，使用 `--new-run`。旧任务和独立工作目录会保留，便于检查，不会被自动删除。若 main 在同步期间发生新的提交，须先按提示将 main 同步到 dev，避免把不完整的分支状态发布。

详情和进度位于 `tools/.tmp/publish-update/`，不进入 Git。当前检出分支和未提交修改不会被脚本切换、重置或临时隐藏。图片、证据与测评附件仍以独立资源包保存，不会重新加入 Git。

## 页面缓存

测评文件与下载链接携带本批校验值。发布后会请求对应批次；如果仍读到旧缓存，会自动重新获取一次。真正不匹配、损坏或不完整的数据继续拒绝评级，不会通过忽略校验来显示等级。

## 评分定义与插件候选包

升级后的强度测评中心以 `data/rating_contract.json` 为评分和玩家解释的来源。同步测评时一并读取它，逐项验证分数、权重和等级阈值一致，再更新 `src/data/rating-contract.json`。旧版插件没有此文件时保留网站现有定义；只有通过分数一致性验证的结果可导入。

插件开发仓库可运行 `Prepare-Release.cmd -RunDirectory "批次目录" -WikiDirectory "Wiki目录"`，从同一份结果生成内置基准候选、当前标准和网站数据，再分别提交、测试和发布。插件包不由网站脚本自动上架。

## 网站回退

先运行 `Rollback-Website.cmd -Version v1.7.5 -DryRun` 确认已有版本及 ZIP、SHA-256 附件齐全，再去掉 `-DryRun` 请求回退。工作流校验原版 ZIP 后部署，不重新计算旧数据，也不改写 Git 标签。在 GitHub Actions 查看结果；恢复新版时按正常发布流程操作。
